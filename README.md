# Booking Weekly Report

Мини-проект по автоматизации и тестированию: Python-скрипт собирает еженедельный отчёт по бронированиям апартаментов из CSV, а 13 автотестов на pytest проверяют его на нормальных и «грязных» данных.

Скрипт написан с помощью Claude (ИИ). Логику я проверял сам: прогонял на тестовых данных, сверял цифры вручную и писал тесты на граничные случаи.

## Что считает отчёт

За неделю (пн-вс, бронь относится к неделе по дате заезда):
- количество броней: всего, подтверждено, отменено
- выручка и средний чек (только подтверждённые)
- количество ночей
- доля отмен, %

## Запуск

```
python weekly_report.py bookings.csv 2026-10-05
```

Вторая дата должна быть понедельником. Пример вывода:

```
Отчёт за неделю 2026-10-05 - 2026-10-11
Всего броней: 5 (подтверждено 4, отменено 1)
Выручка: 1330.00 EUR
Ночей: 12
Средний чек: 332.50 EUR
Доля отмен: 20.0%
```

## Тесты

```
pip install pytest
pytest -v
```

| ID | Что проверяем | Ожидаемый результат |
|----|---------------|---------------------|
| TC-01 | Основной сценарий на bookings.csv | Цифры совпадают с ручным расчётом |
| TC-02 | Дубль booking_id | Бронь считается один раз |

| TC-06 | Пустая цена | Понятная ошибка |
| TC-07 | Отрицательная цена | Понятная ошибка |
| TC-08 | Выезд раньше заезда | Понятная ошибка |
| TC-09 | Неверный формат даты | Понятная ошибка |

## Найденные проблемы (баг-репорт)

**BUG-01. Дубли с разными данными молча игнорируются**

- Серьёзность: средняя
- Шаги: добавить в CSV две строки с одинаковым booking_id, но разной ценой (100 и 150)
- Ожидаемо: предупреждение или ошибка о конфликте данных
- Фактически: берётся первая строка, вторая пропускается без сообщения, в отчёте может быть неверная выручка
- Предложение: сравнивать строки-дубли и сообщать, если они различаются

**Принятое решение (не баг):** бронь, которая пересекает границу недели, учитывается целиком в неделе заезда.
